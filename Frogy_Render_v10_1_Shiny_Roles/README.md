# FROGY v10.1 — Moonlit Swamp & Wall Cling (Render / WebXR)

**This update adds viewer-facing metallic role titles: shiny blue MOD and shiny gold OWNER, displayed above the player name on the same head-tracked nametag.**

**This is the active Node.js/Render/WebXR game, NOT the separate Unity experiment or a Quest APK.** Frogy remains VR-only and intended for Quest Browser. User-supplied Frogy branding is preserved.

## New features

### Timed trigger-to-wall sticking

- **Hold the trigger while your tracked paw is touching a solid lobby/map wall** to stick and suspend gravity. The physical tracked hand remains where the controller is; this does not create another visible hand.
- **One attached paw: 4.5 seconds maximum.** **Both attached paws: up to 7.6 seconds total**, measured from the first attachment in the same grip session. You must keep each trigger held, and **releasing all triggers makes you fall immediately**.
- Slide a connected controller downward to climb upward slightly. A jump releases sticking and preserves previous horizontal momentum. A tiny bar by the attached paw shows remaining duration.
- Contact hysteresis tolerates up to 100 ms of wall collision noise **only while the trigger remains held**. Expired clings require release and an 800 ms reattachment cooldown. Ordinary arm locomotion and right-A jumping continue to work.
- On a map, climbable walls must have a collision shape generated by the game's existing obstacle system; purely decorative vegetation is not climbable. **Real Quest testing is required** for contact comfort, exact reachable surfaces, timing, and tracking.
- With the menu open the trigger still selects menu buttons, rather than attaching to walls. Outside the menu, aiming/weapon trigger actions work when the paw is *not* against a climbable wall.

### Code redemption effects

- A new original, bundled three-tone celebration chime plays on successful code redemption. An animated reward panel and particles appear on the in-headset Codes screen. Failed codes show an error response.
- Existing codes stay as before: `FROG` (+500/+500, once), `FREE` (+100/+100, once), `EMPSH` (OWNER, once, authorized account only), `DJHQW` (+10,000/+10,000, repeatable, authorized OWNER only).

### New MOD code — `IHVDL`

- `IHVDL` permanently unlocks the **MOD** nameplate on an authorized profile, once per profile.
- **MOD and OWNER profiles gain a separate `KICK` button** in the VR Players menu. `REPORT` is still a separate action; reporting someone does **not** automatically kick them.
- A kick removes the selected player from that lobby and blocks rejoining that *same* room for 15 minutes. Kicks are logged and capped to five per hour per moderator. Moderators cannot kick other active MOD/OWNER users. Kicked players can join another lobby.
- **IMPORTANT SECURITY:** Knowing `IHVDL` must not give any stranger the power to remove others. Only Frogy IDs explicitly authorized server-side can redeem it. Under **Render dashboard → Frogy-VR → Environment**, set `FROGY_MOD_PUBLIC_IDS` to a comma-separated list of trusted Frogy IDs. Existing OWNER authorization still uses `FROGY_DEV_PUBLIC_IDS`. A stored title alone is not enough to grant moderation rights after removal from the allowlist.
- Profile roles, nameplates, balances and redeemed codes remain in the saved profile. Persist them with Render Postgres `DATABASE_URL` or an attached persistent disk configured through `FROGY_DATA_DIR`; ordinary Render service files can disappear on redeploy/restart.

### Moonlit swamp gathering lobby

- Rebuilt the **lobby's environment** with dark marsh mud, pond-edge water, crooked boardwalk paths, old cypress trees and roots, moss, reeds, ruins, swamp lanterns and sparse fireflies.
- A faded rug and low benches sit in front of the familiar voting station. **`public/voteboard.js` is untouched**: same position, same selection areas and ray interactions.
- The **seven lily-pad parkour steps**, room computer, cosmetics shop, Tools shop and dressing area are retained. The walkable hub bounds and collision rules remain the same so gameplay interactions aren't silently shifted.
- The environment is still original procedural WebGL geometry, not a photorealistic 3D asset pack. Details are intentionally limited for Quest standalone frame rate.

### Updated first-time tutorial

The first-time tutorial is now four short steps: arm movement, jumping/grabbing, **trigger-held wall sticking**, and the X-button menu + voting.

## Install on existing Render app (MacBook)

**Recommended: replace the contents of your existing Render Root Directory instead of creating a new service.**

1. In **Finder → Downloads**, double-click the `Frogy_Render_v10_1_Shiny_Roles.zip` file to extract it.
2. In your browser, open your existing **GitHub Frogy repository**. Navigate to the directory that contains `server.js`, `economy.js`, `package.json`, and `public/` — this should be the directory Render already builds.
3. Replace those source files with the **contents** of the new `Frogy_Render_v10_1_Shiny_Roles` folder. Keep the `public/` folder structure. Do **not** upload a nested version folder unless you're deliberately changing Render's Root Directory. Do **not** upload saved profiles, tokens, `.env` or local `data/`.
4. Commit the changes on GitHub.
5. Open **Render → Frogy-VR → Deploys**. Wait for the automatic deployment, or choose **Manual Deploy → Deploy latest commit**.
6. If you replaced code inside your existing directory, **leave Render Root Directory unchanged**. If instead you uploaded the whole `Frogy_Render_v10_1_Shiny_Roles` folder to the **top level** of GitHub, set **Render → Settings → Root Directory** to exactly `Frogy_Render_v10_1_Shiny_Roles`.
7. In **Render → Frogy-VR → Environment**, add `FROGY_MOD_PUBLIC_IDS` (trusted Frog ID(s) only). Keep any existing `FROGY_DEV_PUBLIC_IDS` unchanged.
8. On your Quest, open `https://frogy-vr.onrender.com/` in **Meta Quest Browser**. Close and reopen the tab if it still displays an older version. It should identify itself as **v10.1**.

For local server tests on a Mac with Node 22+: `npm install`, `npm test`, `npm start`.

## Testing and limitations

- All 22 automated test suites pass, including the v10 wall-cling, multiplayer moderation, and v10.1 shiny role nametag tests.
- Basic HTTP checks confirmed the game server, the new cling module and sound files are served successfully.
- **Not tested on a physical Quest or inside a fully rendered WebXR headset session.** The browser-render test was unavailable because the headless Chromium binary isn't installed in the test environment. We cannot guarantee that holding the trigger will feel natural or that all scene geometry performs well until a real headset test.
- Quest test focus: stick to a wall with one trigger, stop at 4.5s; use both hands and confirm longer duration; release trigger to fall; climb using a descending hand stroke; jump away; verify menus, weapons and voting still respond correctly. Verify no new duplicate hands.
